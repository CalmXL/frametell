## 架构梳理与图谱产出

为项目产出架构文档 `docs/ARCHITECTURE-MAP.md`（Mermaid 源码 + 目录解剖 + 安全边界表），
包含三张图：组件依赖图、运行时数据流、生产流水线。

### 核实到的关键事实（与直觉不同的几处）

- **包依赖图无环**：`engine`/`models` 是叶子；`voice → engine`；`agent → engine, models, voice`；
  `core → agent, engine, models, voice`；`ui → core`；`cli → 全部`；`desktop → core, ui`。
- **`packages/ui` 对 `core` 只有类型依赖**——全部是 `import type ... from '@frametell/core/types'`。
  因此浏览器包不含 Node 代码，HTTP/IPC 可在运行时切换。
- **`packages/core` 是唯一的行为定义处**：`Studio` 类的每个方法 = 一项客户端能力；
  CLI 与桌面端只做协议翻译。加功能应改 core，不在两个宿主各写一遍。
- **`docs/ARCHITECTURE.md` 的"仓库布局"一节已过时**：它写的是单个 `apps/studio`，
  实际已拆为 `apps/cli` + `apps/desktop`，并新增 `packages/core`、`packages/ui`。已在新文档顶部标注。
- **阶段常量**：`research | storyboard | script | narrate | pages | review | render`
  （定义在 `packages/agent/src/events.ts`，不是 ARCHITECTURE.md 里写的 6 步）。

### 调试入口（已实测）

- 后端：`node apps/cli/dist/cli.js serve --no-open`；token 持久化在 `~/.frametell/server-token`，重启不变。
- 前端热更新：`cd packages/ui && npx vite` → `http://localhost:5173/?token=<token>`（vite.config.ts 已配 /api 与 /p/ 代理）。
- **坑**：仓库无 watch 脚本，`pnpm dev` 等于 `node dist/cli.js`，改 TS 不重新 build 行为不会变。
  可用 `node --watch apps/cli/dist/cli.js serve --no-open` 自动重启。
- **坑**：headless `frametell run` 只读环境变量，不读 `config.json`——与面板行为不同。
- 项目级调试：项目目录即 git 仓库，agent 每步一次 commit；`.studio/events.jsonl` 存全部事件
  （实测某项目 385 条：agent:turn 70、cost 70、tool_start/end 各 57、thinking 40、page 40、stage 14、commit 13、error 4）。
